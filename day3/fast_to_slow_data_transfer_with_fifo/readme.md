# Fast-to-Slow Data Transfer Using FIFO in Verilog

## Overview

This project demonstrates a reliable **fast producer to slow consumer** architecture using a **FIFO buffer** in Verilog.

The system consists of:

1. **face_mod** – A fast module that captures 8-bit input data every clock cycle.
2. **fifo** – An 8×8 synchronous FIFO buffer that temporarily stores data.
3. **mod_out** – A slow module that reads one value from the FIFO every 3rd clock cycle using a Finite State Machine (FSM).
4. **top** – Integrates all modules to ensure that no data generated by the fast module is lost.

---

## Problem Statement

A fast device generates one 8-bit data value every clock cycle, while a slow device can process data only once every three clock cycles.

Without buffering, the data generated during the first two clock cycles would be lost before the slow device can process it.

A FIFO buffer is used to temporarily store incoming data and deliver it to the slow device at a slower rate.

---

## System Architecture

```text
            +-----------+
            | face_mod  |
            | (Fast)    |
            +-----+-----+
                  |
                  | s_out
                  v
            +-----------+
            |   FIFO    |
            | 8 x 8-bit |
            +-----+-----+
                  |
                  | data_out
                  v
            +-----------+
            |  mod_out  |
            |  (Slow)   |
            +-----+-----+
                  |
                  v
                d_out
```

---

## Module Descriptions

### 1. face_mod

**Purpose:** Captures incoming data on every positive edge of the clock.

#### Ports

| Signal | Width | Direction | Description |
|---------|---------|---------|---------|
| clk | 1 | Input | System clock |
| s_in | 8 | Input | Input data |
| s_out | 8 | Output | Registered output data |

#### Operation

On every positive edge of `clk`:

```verilog
s_out <= s_in;
```

---

### 2. fifo

**Purpose:** Buffers data between the fast producer and slow consumer.

#### Features

- Depth: 8 entries
- Width: 8 bits
- Synchronous read/write
- Full and Empty status flags

#### Ports

| Signal | Width | Direction | Description |
|---------|---------|---------|---------|
| clk | 1 | Input | System clock |
| rst | 1 | Input | Reset |
| wr_en | 1 | Input | Write enable |
| rd_en | 1 | Input | Read enable |
| data_in | 8 | Input | Data to be stored |
| data_out | 8 | Output | Data read from FIFO |
| full | 1 | Output | FIFO full flag |
| empty | 1 | Output | FIFO empty flag |

#### FIFO Operation

- Write when:

```verilog
wr_en && !full
```

- Read when:

```verilog
rd_en && !empty
```

---

### 3. mod_out

**Purpose:** Reads one FIFO entry every third clock cycle.

#### FSM States

| State | Description |
|---------|---------|
| S0 | First clock delay |
| S1 | Second clock delay |
| S2 | Read FIFO and output data |

#### FSM Diagram

```text
      +-----+
      | S0  |
      +--+--+
         |
         v
      +-----+
      | S1  |
      +--+--+
         |
         v
      +-----+
      | S2  |
      +--+--+
         |
         +---------> Read FIFO
         |
         v
        S0
```

#### Operation

- Wait for two clock cycles.
- Assert `rd_en` during the third clock cycle.
- Read one data item from the FIFO.
- Repeat continuously.

---

### 4. top

**Purpose:** Connects all modules into a complete data transfer system.

#### Connections

```text
face_mod.s_out   --> fifo.data_in

fifo.data_out    --> mod_out.din

mod_out.rd_en    --> fifo.rd_en

mod_out.d_out    --> Final Output
```

---

## Data Flow

1. `face_mod` captures incoming data every clock cycle.
2. FIFO stores each data sample.
3. `mod_out` requests one FIFO entry every third clock cycle.
4. FIFO supplies stored data to `mod_out`.
5. No data is lost despite the slower processing rate.

## Testbench

The testbench performs the following operations:

1. Generates a clock signal.
2. Applies reset.
3. Sends a sequence of input values.
4. Monitors FIFO and output behavior.
5. Verifies that all data is received in the correct order.

Example input sequence:

```text
1, 2, 3, 4, 5, 6, 7, ...
```

Expected output sequence:

```text
1, 2, 3, 4, 5, 6, 7, ...
```

appearing once every three clock cycles.
